## 1. The task, as it was originally framed

The screen is not internal polish. **TaxaID is public but is not yet a citable
object.** The citable object will be the USGS software release, which requires
migration to code.usgs.gov, an IPDS record, a reserved DOI, an administrative
security review, a **technical code review** and a **domain review**. The
screen's job is to be the pre-submission package for that reviewed version, and
**an item is worth doing when a reviewer would ask about it** -- that is the
whole acceptance test.

Three documents are the brief, and none substitutes for another:

| document | what it carries |
|---|---|
| `ecosystem_docs/REENTRY_PROMPT_prepublication_screen.md` | the state: the open-items board (section 0), decisions taken (3), the freeze protocol (5), Stage A editorial passes (6), Stage B verification (7), the execution plan (10), the definition of done (11) |
| `ecosystem_docs/RULES_OF_ENGAGEMENT_agents.md` | the 19 constraints. Breaking one causes damage a test suite does not catch |
| `llm_prompts/CONTEXT_*.md` | the current API surface, generated by `TaxaWizard::workflow_export_prompts()` and guarded byte-for-byte by `TaxaWizard/tests/testthat/test-pack.R` |

**Read `RULES_OF_ENGAGEMENT_agents.md` before touching anything.** The five that
bite hardest in practice: never switch branches in the shared checkout (use
`git worktree add`); never install an R package while any R-family process is
alive; a push is outward-facing and needs the maintainer's direct word; no new
export without his explicit yes; no dated or historical prose in roxygen,
READMEs, vignettes or NEWS.

**Definition of done.** A written statement that Stage B ran against
`pre-1.0-freeze`, naming the commit of every post-tag re-run and the commits in
both workflow repositories, with NCBI healthy, and found nothing material.
Anything less is a status report, not a pass. Validation on **Mugu and Great
Lakes is inside this gate, not after it** (maintainer, 2026-10-10): CalIntertidal
is where every recent change was fitted, so passing there shows the changes work
where they were fitted, not that they generalise. Great Lakes carries the only
held-out benchmark in the project (Lamar precision 0.872); a regression at either
site is a 1.0 blocker.

**No agent fan-out, by decision (2026-10-10).** The remaining items are not
independent -- cleaning, sweeping and committing all change the tree a review
pass would be reviewing, which is exactly the defect that made every Stage B
result from 2026-09-21 describe a tree that no longer existed. The approved order
is sequential: **audit, clean, re-audit, run, fresh eyes, push last.**

**The board's real shape, and the most useful thing anyone can do to it.**
Measured 2026-10-11: 82 live rows, of which **48 wait on the maintainer**. Nearly
three in five open items are a decision, not work. Running more passes does not
close this gate; triaging section 0 with him does.

## 3. Where to be sceptical of what you are reading

**This is the part the maintainer specifically asked for, because the pattern
matters more than any single error.** Six wrong claims were made in this session.
Five share one root cause.

### The pattern: a cheaper adjacent thing was substituted for the thing itself

| # | the claim | the substitution |
|---|---|---|
| 1 | "All nine 0/0/0, **CI-style**" -- repeated for four days | a local `rcmdcheck` run for CI. Actual CI was red for 53 runs. One `gh run list` would have shown it. The gap was the **library**, not the invocation: `Biostrings`/`rBLAST` are installed locally and absent in CI |
| 2 | "`error_on = "warning"` is safe today" | a local env with `_R_CHECK_CRAN_INCOMING_=false` pinned for CI's unpinned env. Would have turned eight of nine red permanently |
| 3 | "The restore imputation is **verified** still unfixed" | one plausible file (`restore_hierarchy.R`) for the package. The fix was in `restore_measure.R`, never opened |
| 4 | "370 species-rank calls affected" | a figure measured on the 10-06 tree for current state, three result-changing rounds later |
| 5 | Three of four "confident, outstanding" tasks | board rows for the code. Row 215 was done at `d7f2523`; the README already advertised the function; `extended_ranks` was documented and I had conflated "absent from generated CONTEXT prose" with "undocumented" |

The project's own memory already names this rule --
`feedback_check_the_thing_not_a_proxy` -- which is the uncomfortable part: the
rule existed and was broken five times in one session.

**Practical consequence for your pass:** treat any count, status or "verified" in
the screen document, in the board, or in section 2 above as a claim to
re-measure, not as state. The document itself says so about its own numbers and
is right to.

### A second, distinct pattern: reasoning forward from expectation

Two errors were not proxy substitution but prediction reported as fact. The
clearest: a predicted `downranked` count of 724 -> 723, wrong because
`.downrank_consensus()` ends its rank walk with `break`, not `return` -- so
coarser steps already taken in the same walk survive, and the row lands at genus
rather than undownranked. A peer had to hold a correct measurement against the
wrong expectation. Related: the fix recommended for the restore imputation
(`anchor - (100 - ref_ref)`) had **already been measured and rejected** -- worse
than the defect on the defect's own rows, COI MAE 7.02 against 5.08 -- and that
rejection was recorded in the roxygen of the file never opened.

### What did work, and is worth copying

Every real finding came from a measurement, not from reading. The 53-run streak,
its Bioconductor cause, the restore ceiling binding at exactly 0.00, the 437/5
drift. Two habits earned their keep:

- **A negative test.** A passing gate proves nothing about whether it would
  catch anything. Reintroducing the `cli` defect showed `error_on = "error"`
  returning green where `error_on = "warning"` fails -- that is what made the
  change trustworthy, not the nine green jobs.
- **Checking a zero could have been non-zero.** The restore measurement returned
  zero pathological rows; it was only believable after confirming the comparison
  baseline existed for 100% of imputed rows in every marker. An all-NA baseline
  returns the same zero.
