## Prioritized list — every row that is NOT sound = YES

### H — could flip which taxon wins a species-level call (14)

1. **TaxaAssign :: compute_posterior :: mc_uncertainty_propagation** — This Monte Carlo path is the live winner path (`posterior_consensus()` defaults `posterior_col = "posterior_mean"` = the MC mean). Normal likelihood draws are clamped at 0 (a spurious point-mass, not a truncated density), and the hard `alpha < 1` J-shape override misses near-J-shaped priors (`1 < alpha ≲ 2`), asymmetrically favoring concentrated priors over diffuse ones of higher mean. → Replace the Normal-clamp with a proper truncated-normal/positive-support likelihood; validate and widen the `alpha` cutoff against the real prior-`alpha` distribution `join_priors()` actually produces. **STATUS: partially fixed (Session 149)** — likelihood draws now use exact truncated-normal sampling (no more spurious point mass at 0), and the guard was widened from `alpha < 1` to `alpha <= 1` (closes the exact-boundary case, confirmed ~14-20% of bundled-fixture rows). The `1 < alpha ≲ 2` continuum is deliberately still open — no real `prior_alpha` distribution large enough to set a data-justified threshold was available this session. See `TaxaAssign/CLAUDE.md`'s Session 149 note.
2. **TaxaAssign :: score_consensus :: rank_threshold_capping** — **RESOLVED (Session 149) — this was a documentation gap, not a code defect.** The user clarified this function's actual purpose: it exists to *reproduce* a conventional fixed-threshold pipeline's decision rule (GITA/Jonah Ventures-style), so a user can run the same match data through both `score_consensus()` and TaxaID's own Bayesian pathway and compare what a conventional pipeline would have called against what TaxaID calls. Given that purpose, percent-identity's inability to discriminate species from congener (Session 147 ROC sweep) is not a bug here — it's a faithful reproduction of the same limitation those conventional pipelines actually have; "fixing" it would defeat the comparison the function exists to provide. The original recommendation below (gate on reference completeness / route through the bivariate-normal path) would have been a mistake — that's `posterior_consensus()`'s job, not this one's. Fix applied: roxygen now states this purpose explicitly (`@section Purpose`) and reframes the "why rank_thresholds defaults to non-NULL" note — the default isn't there to make species-level calls "safe," it's there so the reproduction matches a real pipeline's behavior (no actual pipeline omits rank thresholds) rather than an accidental TaxaID-only permissive default. No behavior change; docs-only. Downgraded from H — function is sound for its actual purpose. *(Original finding, superseded: fixed per-rank %-identity thresholds only protect a species call when the true congener is itself a reference hit; when the congener is absent from the reference, a lone 99% hit still clears the threshold — see above for why this is expected, not a defect.)*
3. **TaxaAssign :: join_priors :: dark_diversity_floor** — Assumes unmodeled species are exchangeable draws from one detection process. Domestic/synanthropic/human taxa violate this in a known, systematic direction: GBIF/iNat structurally under-index captive organisms, so e.g. *Felis catus* gets the same ~0.00006 floor as a geographically impossible candidate — empirically confirmed to flip a real camera-trap cat call. → Implement the deferred TaxaFlag domestic-species-floor flag, or give a curated exception list a non-floor prior. **MITIGATED (Session 149), still H.** User's design split the fix two ways rather than "fixing" `join_priors()` itself (which still assumes exchangeability — that hasn't changed): (a) priors — documented, not coded: `TaxaExpect::generate_undetected_diversity()` and `join_priors()` now carry an explicit `@section`/roxygen note recommending users augment occurrence data with known local domestic-species presence before training, since the likelihood side (NCBI BLAST, iNaturalist image recognition) already handles domestic species fine and this is purely a training-data gap; (b) `TaxaFlag::add_posthoc_assessment()` gained opt-in `domestic_taxa`/`domestic_prior_source` params that re-label the resulting strong-likelihood-vs-low-prior contrast as `"domestic_prior_caveat"` for review. Still flagged H because both mitigations are opt-in (a user who doesn't read the doc note or doesn't pass `domestic_taxa` gets no protection) and no production workflow wires `domestic_taxa` in yet — downgrade to M once that's true for the study types where it matters.
4. **TaxaAssign :: join_priors :: coarse_rank_expansion_credible_set** — Expanded species rows all inherit one flat (uninformative) likelihood, so a family-level identification resolves to a *specific species* purely by occurrence prior; species outside `taxaexpect_priors` coverage are silently excluded from the renormalized candidate space. → Cap the reportable rank of a purely prior-expanded winner (or flag it as prior-driven); verify species coverage before treating the renormalized set as exhaustive. **FLAGGED, NOT CHANGED (Session 149) — explicit user direction: this is intended behavior.** Clarified with the user via a concrete example (a family-only camera-trap ID expanded into two same-family species sharing one inherited likelihood, winner decided by local occurrence prior alone) that this is a deliberate design choice (use priors to resolve an otherwise-unresolvable coarse ID), not a defect — and also confirmed it's a *different* mechanism than `TaxaMatch::filter_redundant_hypotheses()` (already called at the end of `join_priors()`), which handles the separate, already-solved case of a genuinely redundant coarser-rank row coexisting with a real finer-rank row for the same observation. Fix: `posterior_consensus()` gained `winner_hypothesis_type`/`winner_rank_expanded` output columns so a downstream consumer can now distinguish a prior-only-resolved species call from a genuinely evidence-resolved one — visibility, not behavior change. Still CONDITIONAL/H in the sense that the underlying mechanism is unchanged (a coarse ID can still surface as a confident-looking species-level `consensus_taxon`); the new columns make it possible to tell the difference, not less likely to happen.
5. **TaxaAssign :: update_prior_from_consensus :: presence_multiplier_empirical_bayes** — An unvalidated fixed ×5 prior boost is explicitly designed to change unresolved winners (10% → ~33% at ×5), applied regardless of how many neighbors confirmed the species or how confidently. → Implement the roxygen's own disclosed Beta-Binomial hierarchical alternative, or at minimum scale the multiplier by confirmation count/confidence; validate the flip rate on real within-site data. **FIXED (Session 149), reclassified CONDITIONAL.** Replaced by a confirmation-quantile design reached through an extended discussion working through and rejecting several alternatives on the record: max-confidence donor (circularity is a non-issue by construction, but doesn't use confirmation count); noisy-OR combination across donors (shown numerically to let many correlated/confused confirmations manufacture unwarranted confidence for either of two mutually-confusable species — renormalization does NOT correct this once a third, unrelated candidate exists); plain max alone (does "scale with N" via extreme-value theory, but this does not protect against the confusable-species case either, and a sample max is *more* volatile to a single outlier than an aggregate, not less). **Landed on:** the `confirmation_quantile`-th quantile (default 0.9) of confirming donors' `consensus_posterior`, gated by `min_confirmation_confidence` (default 0.8, disableable), substituted for `prior_mean` only where it exceeds the existing value (never-demote). Justification: unlike a sample max, a sample quantile converges to a *stable population value* as the donor pool grows, rather than drifting toward the degenerate ceiling of 1.0 regardless of whether the evidence is real — for a genuinely confusable pair, both sides' quantiles converge to the *same* value (restoring symmetry); for a genuinely separable species, its true quantile sits above the confusion-noise floor (preserving discriminating power). Also fixed a latent `prior_alpha`/`prior_beta` staleness bug found along the way (only `prior_mean` was previously rescaled, leaving the Beta shape sampled by `compute_posterior()`'s Monte Carlo path inconsistent with the boosted point estimate). Still CONDITIONAL, not YES: the quantile level and confidence floor are both unvalidated placeholders (same caveat as every other threshold in this review), and — flagged explicitly, not solved — a quantile still can't distinguish confidence earned by genuinely strong evidence from confidence attained despite thin/low-quality input (e.g. a short DNA read producing a spuriously perfect match). That gap is now tracked as its own deferred design thread (a quality covariate on match scores); see [[project_quality_covariate_deferred]].
6. **TaxaExpect :: generate_undetected_diversity :: global_floor_beta** — `N`/`N_total` is pooled across all taxonomic groups by default, making the "undetected species" floor too low for a minority group on a marker biased toward another group. → Stratify `N`/`N_total` per taxonomic (detection-process) group; compute a per-group floor Beta(1, N_group−1). **MITIGATED, still H.** `TaxaExpect::estimate_kernel_priors(sampling_group_col=)` computes its Kish effective sample size (the current path's analogue of `N_total`) separately for each detection-process group when a grouping column is supplied, and `generate_undetected_diversity()` accepts that per-group prior object directly — its Beta-Binomial global-floor logic runs on whichever `N`/singleton set the fit provides, giving each group its own correctly-scoped floor with no change needed inside `generate_undetected_diversity()` itself. Confirmed on real PtConception 18S data: pooling `macroinvertebrates`+`other_vascular_plants`+`zooplankton` into one `N_total` (145,442) gives `zooplankton` a floor ~34× too low relative to its own group's true effort (2.36e-4 vs. 6.9e-6) — a real, empirically confirmed dilution, not a hypothetical one. Still flagged H: `sampling_group_col` is opt-in (a caller who fits the prior estimator without it still pools every taxon into one `N`/floor), and per-workflow adoption should be verified rather than assumed.
7. **TaxaLikely :: train_likelihood_model :: eb_bivariate_normal** — The continuous bivariate-normal model form (Framing B) is empirically validated only for 12S and 18S at PtConception, yet the same code now trains on COI/16S/cytb/rbcL/matK/trnL reference sets via `trim_to_amplicon()` with no re-check. H1 pairs are also treated as independent when they are O(k²)-correlated (all pairwise combinations of the same k sequences). → Run `diagnostics/seq_matrix_score_distribution.R` per new marker before trusting the model there; down-weight the shrinkage weight to `n_sequences`, not `n_pairs`. **PARTIALLY RETRACTED (Session 151), reclassified CONDITIONAL — the shrinkage-weight half of this finding is a false positive, verified empirically before touching anything.** Built a synthetic 5-sequence species and ran it through the real pipeline: `.prep_training_data()` does generate all `k(k-1)` ordered within-species pairs internally, and a separate `N_Obs` diagnostic column does carry that raw pair count — but `group_by(id_x) |> slice_max(score_logit, n=1)` (present since the package's initial commit, not a recent fix) collapses this to exactly one row per SEQUENCE — its single best within-species match — before `train_likelihood_model()` ever computes the shrinkage `N`. Confirmed directly: for the 5-sequence synthetic species, `N_Obs` = 20 (pairs) but the `n_obs_species` actually used in `w = N/(N+prior_weight)` = 5 (sequences). `N_Obs` itself is dead code with respect to shrinkage — grepped the whole package, it's never read again after being computed, and doesn't even survive into the returned `model_params` object (`H1_Lookup` only carries `lookup_key`/`rank`/`mu_score`/`mu_gap`/`sigma_score`). Docs-only fix: `N_Obs`'s roxygen in `.prep_training_data()` now states plainly it's an unused pair-count diagnostic, not the shrinkage N; `train_likelihood_model()` gained a `@section Marker validation scope` stating the 12S/18S-only validation scope and pointing at `diagnostics/seq_matrix_score_distribution.R` for any other marker. Kept `N_Obs` rather than removing it (per the user's explicit choice) — it costs nothing computationally (already derived from an intermediate the code computes anyway) and could be a legitimate future pair-density diagnostic. **Still open, correctly characterized:** the per-marker validation gap itself — nothing currently blocks training on an un-validated marker, or warns when one is used; this remains a real, actionable "run this diagnostic first" workflow gap for anyone applying `train_likelihood_model()` to COI/16S/cytb/rbcL/matK/trnL data, exactly as the original finding said, independent of the shrinkage-weight correction above. `devtools::test()` 658/658 unchanged (docs-only), `check()` clean.
8. **TaxaLikely :: evaluate_likelihoods :: h1h2h3_bivariate_likelihood** — The taxon-selection step itself relies on fixed, unvalidated H2/H3 mean offsets (`H3_delta = H2_delta + 2.0` is a bare constant); wrong offsets directly shift mass between "named species" and "unreferenced." → Estimate the H3 delta from genus-level foreign-match data (the code already flags this as low-priority — raise it); sensitivity-test both deltas against real congeneric ground truth in the seq_matrix data. **PARTIALLY FIXED (Session 151, by a separate agent working directly in TaxaLikely; independently code-reviewed and re-verified here).** `H2$delta` — the more load-bearing half of this finding, since `H3$delta` is defined purely as `H2$delta + 2.0` — was a single value pooled across every genus in the training set, silently treating a cryptic species complex (real congeneric divergence far tighter than the pooled average) the same as a loosely-differentiated genus. Fixed: `.prep_training_data()` gains `max_congener_score` (best same-genus/different-species match, `NA` when the genus has no second referenced species — distinct from the pre-existing `max_foreign_score`, which mixed in any-genus matches); `train_likelihood_model()` uses it to estimate a genus-specific H2 delta wherever a real congener pair exists, Empirical-Bayes-shrunk toward the pooled value via the identical `w = n/(n+prior_weight)` form already used for per-species H1 means, stored in a new `H2_Lookup` slot (`NULL` when no genus qualifies — old model_params objects and old code paths are unaffected, confirmed backward compatible). `evaluate_likelihoods()` prefers the anchor candidate's genus-specific delta at inference when available, and every H2/H3 row now carries `h2_delta_source` (`"genus_specific"` vs `"global_fallback"`) so a caller can identify rows still using the cruder pooled approximation — including every genus with only one referenced species, where no local estimate is possible at all. Independently re-verified: re-ran the full suite (656/656, 0 failures, up from 643) and `check()` (0/0/0) directly rather than trusting the reported numbers; traced the `rank_code_b` = genus derivation in `.generalize_ranks()` by hand and confirmed it's consistent with `evaluate.R`'s independent `genus_rank_col` derivation for any `rank_system` length ≥ 2; confirmed the Fundulus (tight congener pair)/Distant (monotypic) test fixture actually isolates the intended distinction. **Still open, not addressed by this fix** (explicitly, not silently): the `H3 = H2 + 2.0` additive step-size itself remains exactly as unvalidated a constant as before — this fix only ever changes the H2 base it's applied on top of; the single-anchor structural limitation (H2/H3 only ever evaluated for the best-scoring candidate's own genus — see this package's own "Known Footguns" section) is untouched; and evidence-similarity-tracking-phylogeny is now explicitly documented (`inst/TaxaLikely_supplemental_methods.md`) as a real, permanent limitation for image/acoustic mimicry/convergence that no version of this fix can address. Still CONDITIONAL/H for genera without real congener data (the common case for a sparse reference database) and for the H3 step-size question, which is now a cleaner, more clearly-scoped remaining item than before.

10. **TaxaLikely :: apply_coverage_constraints :: completeness_penalty_weight** — Default `penalty_factor = 0` hard-zeros the "unreferenced species" hypothesis, encoding *certainty* that a genus census (`audit_barcode_coverage()`'s `is_complete`) is a ground-truth-complete enumeration — but that's itself an NCBI-query estimate (missing/renamed taxa, synonymy). Wired into `TaxaLikely/inst/workflows/sequence_likelihood_workflow.R` (the one real production-shaped workflow calling `build_sequence_matrix()` without an existing manual length safeguard), passing the same `BARCODE_TERM` already used at its fetch step. 12. **TaxaMatch :: blast_sequences :: score_window** — This filter decides which candidates TaxaLikely/TaxaAssign ever see. A fixed 2-pt tolerance window can drop a true species sitting >2 pts below a congeneric top hit before the likelihood model ever runs — exactly the discrimination-failure zone the sibling-package ROC sweep identified (that sweep critiques a different function's use of raw percent-identity, so it's cited-but-doesn't-support-this-use, not a direct validation). Field-tested only on 5 easy queries with clear top hits ≥98%. → Run a leave-one-out check of `score_range` against the real 12S reference data (how often does the true species sit beyond the window below its congener?); widen the default or make it marker-adaptive if material. **FIXED (Session 151), reclassified CONDITIONAL.** Ran exactly the recommended leave-one-out check (new `diagnostics/score_window_leave_one_out.R`) against three independent real reference-vs-reference distance matrices, not a synthetic fixture: for each reference sequence, treat it as a leave-one-out query against every other sequence in the same matrix and ask whether a congener outscores its own true species, and by how much. Result confirmed the risk is real, not hypothetical: Sebastes (54 species) 3/113 congener-outscoring events, all trivial (0.6 pts, none dropped at the old default); **Chromis (26 species) 3/33 events, 4.7-7.1 pts — all three would have been silently dropped at `score_range = 2`**; a real 6-genus PtConception 12S set 1/11 events, 2.5 pts, also dropped at the old default. Pooled: 4 of 7 real congener-outscoring events (57%) exceeded the old 2-pt default and would have silently excluded the true species from every downstream step, with zero signal to the user that it happened. Fix: default `score_range` widened `2` → `8`, covering every gap actually observed in this check with margin — explicitly documented as an evidence-backed starting point given what has been measured, not a guarantee against a more divergent case; `max_hits` (default 20, unchanged) bounds the resulting candidate count regardless of window width, and a wider window is precisely what preserves TaxaLikely's "gap" feature (`train_likelihood_model()`'s own key H1/H2/H3 discriminator) for the bivariate-normal model to actually use downstream — this connects directly to this doc's own cross-cutting pattern #3 (a real fix routes species-vs-congener discrimination through the bivariate-normal path rather than a raw-percent-identity threshold): widening the coarse pre-filter is what actually lets that routing happen, instead of the pre-filter silently deciding the case itself. Two real workflow scripts using the old value explicitly (`blast_sequences_workflow.R`, `workflow_fastq_to_match.R`) updated to the new default. New test pins the default at `8`. `devtools::test()` 451/451 (unchanged count, one new test), `check()` clean.

## Cross-cutting patterns worth the user's attention

1. **The MC/live-winner path in `compute_posterior()` is the single highest-leverage fix.** Because `posterior_consensus()` defaults to `posterior_mean` (the Monte Carlo mean), the 0-clamped Normal likelihood and the `alpha<1` J-shape cutoff (row H1 above) sit upstream of *every* species-level call in the Bayesian pipeline, not just one function.
2. **The domestic/synanthropic-species floor artifact recurs across 4 packages** (TaxaExpect's `global_floor_beta`/`singleton_mirror_beta`, TaxaAssign's `dark_diversity_floor`/`hierarchical_dark_diversity_groups`, TaxaFlag's `tier_likelihood_classification`, `flag_contaminant` explicitly ruled out) — this is a single upstream data-curation fact (GBIF/iNat under-index captive organisms) whose fix belongs in one place (the deferred TaxaFlag flag) rather than four separate patches.
3. **Percent-identity threshold logic (`score_consensus`, `blast_sequences::score_window`) is used in two different packages to do the same job the ecosystem's own Session 147 ROC sweep says percent-identity fundamentally cannot do** — discriminate a true species from its closest congener. Both rows are H priority for the same underlying reason; a real fix likely means routing species-vs-congener discrimination through the bivariate-normal (TaxaLikely) path in both places rather than patching each threshold separately. **Update (Session 151):** `score_consensus` was resolved as intentional (item 2 — it deliberately reproduces a conventional pipeline for benchmarking, not a defect). `blast_sequences::score_window` (item 12) was genuinely fixed in this direction: rather than trying to make the coarse pre-filter itself discriminate species-from-congener (which the ROC sweep already showed raw percent-identity can't do reliably), its default was widened so it stops *deciding the case itself* by dropping the true congener before the bivariate-normal model ever sees it — the actual discrimination is left to `TaxaLikely::evaluate_likelihoods()`'s gap-aware H1/H2/H3 model downstream, as this pattern's note originally recommended.
4. **`correct_training_bias()`'s default `tau=1.0` is the one outright reversible bug in this review** — every real calibration the ecosystem has run says `tau≈0`; the default should change, not just get a caveat.
5. **Prior-side, not likelihood-side, is where most of the H findings cluster** (TaxaExpect and TaxaAssign contribute 6 of the 14 H rows). The likelihood/scoring side is comparatively more validated (TaxaLikely's Framing B bivariate-normal, TaxaAssign's `score_consensus`/`combine_multisite_priors` groundwork) — but its extension to markers beyond 12S/18S, and to `correct_training_bias`/`apply_coverage_constraints`'s defaults, are real open gaps.
6. **A component the original cataloging pass missed entirely: `expand_unreferenced_hypotheses()` (moved TaxaAssign → TaxaLikely, Session 150) implements "borrow a likelihood value from referenced relatives" for named unreferenced species — and it is the *third* independent implementation of that same concept, not caught as a set until a concurrent, separately-motivated package-placement review (mapping the ecosystem onto the user's manuscript's 4 conceptual pipeline steps) surfaced it.** The other two are already separately flagged in this review: item 18 (`TaxaAssign::assign_taxa_llm::score_to_likelihood_softmax`, M priority — unreferenced congeners get the median exponentiated score of referenced ones) and `TaxaLikely::assign_scores::softmax_ratio_normalization` (M priority — H2/H3 likelihoods approximated by median H1 likelihood of same-genus/-family candidates). All three use essentially the same "median-of-relatives" heuristic, independently, in three different code paths (score-based, LLM-based, and the general bridging function) — none cross-reference each other, and none has ever been validated against the other two for consistency. Package-placement itself was fixed (Session 150, purely structural, no algorithm change); the underlying "is median-of-relatives the right heuristic, and should there be one implementation instead of three" question remains open and is now the more clearly-scoped version of a concern this review had only surfaced piecemeal. Worth a dedicated look when the review reaches this territory again, rather than continuing to patch each of the three sites independently.
